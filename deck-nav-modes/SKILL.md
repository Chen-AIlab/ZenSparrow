# Deck Nav Modes · 演示材料导航模式生成

## 这个 Skill 做什么

根据用户的**演讲场景**推荐合适的网页演示导航模式，并生成对应结构的 HTML 演示材料 + 浏览器试看版本。解决"内容有了，但不知道用哪种翻页/跳转方式最合适"的问题。

> **边界声明**：本 skill 只解决"怎么翻页/怎么跳转/怎么组织页面结构"的问题，**不解决**配色、字体、品牌主题与复杂版式设计。视觉风格由用户偏好或其他设计类 skill 负责；本 skill 生成的默认浅色主题仅为中性占位。**如果用户已提供品牌色/字体变量**：生成时直接替换 `:root` 中的 `--paper`、`--ink`、`--accent`、`--sans` 等变量即可，不要额外发明新的变量体系；design-tokens.md 中的层级、间距、容量规则仍然全部适用。

## 6 种登记模式

| # | 模式 | 一句话 | 典型场景 |
|---|------|--------|---------|
| M1 | 线性 Linear | 一页接一页顺序放映，键盘/滚轮/触屏翻页 | 正式演讲、限时汇报、发布会 |
| M2 | 目录中心 Hub & Spoke | 目录页卡片点击进入详情页，可返回再进其他主题，支持二级目录 | 内部研讨、评审、展台演示、答疑多的场合 |
| M3 | 混合 Linear + Hub | 主干线性播放，目录随时可呼出跳转 | 正式演讲但预计被提问打断 |
| M4 | 长页滚动 Scrolling | 单长页纵向滚动 + 滚动动效 | 会后传阅、手机查看、产品宣传页 |
| M5 | 时间线主轴 Timeline Hub | 可点击时间线/路线图作目录，点击节点进详情 | 规划排期、年度总结、项目复盘 |
| M6 | 缩略图总览 Grid Overview | 全部页面缩略图平铺，点击放大进入，ESC 退回 | 20 页以上的大材料、培训课件 |

**详细结构、代码骨架与注意事项：生成前必读 `references/modes.md` 中对应模式的小节。**

## 预览文件（先试看，再决定）

`assets/preview/` 是一套开箱即看的"模式体验馆"演示站点：同一套虚构内容（星环 X1 发布会）分别用 6 种模式实现，入口 `index.html` 是模式总览，每张卡片进入对应模式的真实可玩 demo（M1–M6 均可完整操作、可返回总览）。

**定位**：preview 是模式**选型工具**，不是用户内容的实时预览，不与用户后续生成的材料同步。用户选定模式后，基于 preview 中对应 demo 的骨架填入真实内容，生成新的试看版本交付。预览站点的 M6 缩略图为预生成静态图片；若环境无法渲染图片，缩略图槽位会自动隐藏，不影响导航操作体验。

**触发打开演示的说法**（用户说这类话时，直接打开 preview，不要现场生成）："让我看看效果"、"有什么模式可选"、"先体验一下"、"打开演示"、"对比一下几种模式"、"把体验馆/演示站点打开"。

操作步骤：
  1. 若 `/mnt/agents/output/app` 已有用户内容，先整体备份（复制到同级命名清晰的备份文件夹），并提醒已有版本快照可回滚
  2. 把 `assets/preview/` 全部内容复制到 `/mnt/agents/output/app/`
  3. `build_version`（type html）保存试看版，告诉用户每个 demo 左上角可返回总览
- 用户选定模式后，基于 preview 里对应的 demo 骨架填入真实内容，比从零写更快也更稳定
- M6 的缩略图是静态截图（`images/m6-thumb-*.png`）；换成真实内容时需重新截图并替换同名文件

## 工作流

### Step 1 · 场景对齐（必做）

用户没明说模式时，问 1-3 个关键问题再推荐，不要替用户猜：

1. **场合**：正式演讲 / 内部研讨 / 展台演示 / 会后传阅？
2. **互动程度**：会被打断提问、需要自由跳转吗？
3. **规模与载体**：大约多少页？投屏演讲还是手机/电脑上自己看？
4. **单页内容密度**：以"一句话 + 一张图"为主，还是以数据 / 表格 / 多模块为主？（低密度偏线性或长页滚动；高密度偏目录中心或缩略图总览）

推荐时用上面的决策表，并**说明推荐理由**；给出 1 个首选 + 1 个备选让用户确认。用户已明确指定模式（"我要目录点击那种"）则直接进入 Step 2。

### Step 2 · 生成演示材料

- 所有模式都生成纯 HTML/CSS/JS（单文件或多文件），项目放在 `/mnt/agents/output/app`。
- **M1 线性**：单文件多 `<section>` + 翻页 JS。可直接改造 `assets/linear/deck.html`（含键盘←→/滚轮/触屏/ESC 索引/dot 分页，改内容即可用）。
- **M2 目录中心**：多页面站点。可直接改造 `assets/hub-spoke/`（`index.html` 目录页 + `shared.css` + `topic-01/02/03.html` 三个独立详情页骨架，开箱即可运行；含固定返回按钮、卡片悬停动效、二级目录写法示例）。
- **M3-M6**：按 `references/modes.md` 对应小节的骨架组装；M3 有现成可运行骨架 `assets/preview/m3.html`（线性轨道 + ESC 呼出章节菜单），直接改造即可；M6 的缩略图用 CSS `transform:scale` 的 iframe 或截图生成。
- 视觉风格（配色/字体/卡片语言）不在本 skill 范围内——用户有偏好按用户偏好，无偏好时用克制的浅色默认主题；不要在本 skill 里发明品牌主题体系。
- **可修改性**：用户后续常要自己改内容。在 HTML 里写好编辑注释（"改文字找这里"、"图片放 images/ 目录"），图片用 `onerror` 自动隐藏的空槽位，视频给注释好的 `<video muted loop playsinline>` 替换示例。

### Step 3 · 保存试看版本（必做，不可省略）

**前置依赖**：本流程依赖 `website_version_manager` 工具保存试看快照。分两条路径：

- **环境有 website_version_manager**：
  1. 确认入口存在：`/mnt/agents/output/app/index.html`（M1 单文件也要命名为 index.html；若环境工作目录不同，替换为实际目录即可，下文同）。
  2. 调用 `build_version`：`type="html"`，`project_dir="/mnt/agents/output/app"`，`message` 用 ≤6 个词的版本名（如"线性模式·试看版"）。
  3. 回复用户：版本已保存 + 可打开预览；只使用工具返回的 URL/ID，不要自己拼链接。
  4. 用户要求"恢复到某版本"时，用 `rollback` + 同一 `type` 和 `project_dir`。
- **环境没有该工具**：如果环境中还有其他静态站点部署/预览工具（名称不限），可用它替代完成"保存快照 + 返回链接"这一步；如果完全没有此类工具，直接把项目保存到工作目录（如 `/mnt/agents/output/app`），告知用户本地路径和入口文件，并说明"当前环境无法生成在线预览，可用任意静态服务器或浏览器直接打开 index.html 查看"。不要为了模拟预览而虚构链接。

### Step 4 · 迭代

用户看完试看版想换模式时：保留内容文本，只重构导航骨架（M1↔M2 互换最常见——把 `<section>` 拆成多页加目录，或把多页合回单文件），再保存新版本。

## 硬规则

**视觉稳定性总规范：生成任何页面前必读 `references/design-tokens.md`**——它约定视觉聚焦（锚点/安全区/动效幅度上限）、字号五级阶梯、8pt 间距刻度、单一强调色用量、单页信息容量上限、深浅页节奏和逐页自检清单。以下几条是最常违反的红线摘要：

- 一次交付只用一种主导航模式；M3 是唯一允许的复合形态。
- 每个模式都必须有"回到全局"的手段：M1 的 ESC 索引、M2/M5 的固定返回按钮、M6 的 ESC 退回总览。
- 详情页/正文页布局必须同构：同等级页面用同一骨架、同一边距，页眉与标题在所有页像素级同位（视觉聚焦），避免每页格式漂移。
- 字号只允许落在五级阶梯内（14px 为绝对下限）；间距只允许 8 的倍数；内容超上限时拆页，不许缩字号硬塞。
- 不要把试看版本说成"已发布/已上线"——只是保存了可预览的版本快照。
